# M5 installer and first-run status

Implemented in this checkout:
- `peke setup` stores local model/runtime settings under the platform user config directory.
- `peke launch` starts setup when no user settings file exists, otherwise opens the GUI.
- `peke update` and `peke uninstall` wrap pipx and retain user configuration.
- `install.sh` and `install.ps1` resolve a stable GitHub Release (or a requested `PEKE_VERSION`), download the Peke wheel, `requirements-hashed.txt`, and `SHA256SUMS`, and verify both downloaded artifacts before installation.
- Release CI uses pinned uv version 0.10.0 to generate a release-specific runtime lock with hashes. Installers install the local wheel without dependency resolution, then install the locked runtime dependencies with pip `--require-hashes`.
- Release CI tests POSIX installer syntax and dry-run behavior on Linux/macOS, parses and dry-runs the PowerShell installer on Windows, checks built wheel/sdist contents, smoke-installs the wheel without resolving dependencies, and uploads a SHA-256 manifest with release assets.
- Source distribution inclusion explicitly covers installer scripts and install documentation.

Still outstanding before calling installer security production-hardened:
- The Peke wheel is verified against a manifest delivered by the same GitHub Release; the manifest is not independently signed. This protects against corruption/mismatched assets, not a compromised release account or release pipeline.
- The lock is generated by CI at release time rather than committed as `uv.lock`; the exact lock used by each release is published as an asset, but rerunning a release build later could resolve newer compatible versions.
- The checksum manifest is delivered by the same GitHub Release and is not independently signed, so it does not defend against a compromised repository account or release pipeline.
- The bootstrap still requires Python 3.10+ and pipx to be installed beforehand. Native source builds can also need build-system dependencies or a local compiler toolchain outside the runtime lock.
- CI exercises syntax and dry-run behavior cross-platform, but does not perform a full live install/uninstall on clean Windows/macOS/Linux machines or verify native llama-cpp builds on every target.
- PowerShell execution was not available in the current editing environment; its parser/dry-run check is configured in Windows CI but has not run in this session.

No model weights are downloaded automatically. Uninstall intentionally retains user configuration.
